# 变更模拟与波及面度量

原理:扩展性 = 实施一个预判变更的波及面。T2 扩展点的变更应"只新增、不修改"(OCP)。

## 四指标(在独立 worktree 实施变更后度量)

度量前先在 worktree 内 `git add -A`(统一把工作区变更并入索引,porcelain 的 A/M 前缀与 staged diff 才可靠):

| 指标 | 定义 | 命令 |
|------|------|------|
| 新增文件数 | git 新增(A)文件数 | `git status --porcelain \| grep -c '^A'` |
| 修改既有文件数 | 既有文件被修改/删除/重命名(M/D/R/T)数 | `git status --porcelain \| grep -cE '^[MDRT]'` |
| 修改行数 | staged diff 新增+删除行(含新文件,仅记录不作门禁) | `git diff --cached --stat` 末行汇总 |
| 既有测试破坏数 | 因变更失败的既有测试数 | 实施后跑测试套件,失败数 - 基线失败数 |

(grep -c 计数为 0 时退出码非零;在 set -e 下使用须对各命令追加 `|| true`)

## 达标判定

T2 变化点达标 ⇔ **修改既有文件数 = 0** 或全部修改落在该点 ADR"迁移触发条件"声明的文件内;且**既有测试破坏数 = 0**(允许新增测试)。不达标 = H 级发现。

## 抽样策略

可能性(H=3,M=2,L=1)× 影响面(H=3,M=2,L=1)加权分降序,取 top 2~3;用户可增删/指定;大项目可降至 1 并在报告标注。

## 流程

```bash
git worktree add ../demo-sim-{CP-ID} -b sim/{CP-ID}   # 1 独立 worktree
# 2 实施最小真实变更(如新增一个支付渠道的完整接入)
# 3 git add -A 后度量四指标并判定
git worktree remove --force ../demo-sim-{CP-ID}        # 4 默认回滚;保留须用户确认
```

无 git 环境:复制仓库到临时目录 `/tmp/...` 副本上模拟,报告标注降级;复制前先提交或清理基线脏文件,否则度量会把脏文件一并计入。

## 陷阱
- 只改一行"接线"就宣称接入成功 ≠ 完整实施:变更须达到"可被真实调用"的完成度
- 基线测试本来就有失败:先记录基线失败集,破坏数只计新增失败
