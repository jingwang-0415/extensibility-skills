# 预设扩展模式目录(11 个)

T2 变化点必须优先从本目录选用机制。每个模式抽象成本 ≤1,与成本上限"≤一层抽象+文档"对齐。

| 模式 | 适用信号 | 抽象成本 | 反例(不该用) |
|------|---------|---------|--------------|
| 策略 Strategy | I1/I2, B1, B3, D3, S1/S2/S3, U2 | 1 接口 | 变化维度只有单一实现且无替换迹象 |
| 插件注册表 Plugin Registry | I2, B3, C3, U3 | 1 注册点 | 调用方固定、无第三方扩展诉求 |
| 防腐层 ACL | I1, I3, T1/T2/T3 | 1 边界层 | 内部模块间通信(过度隔离) |
| 适配器 Adapter | C1, I3, T1/T2/T3, U1 | 1 包装层 | 仅为包装而包装、语义未转换 |
| 配置外置 Config | P1/P2/P3, B1, U1 | 0 | 用配置承载业务流程分支 |
| 特性开关 Feature Flag | P2, P1 | 0 | 长期存活的开关(应为正式分支) |
| 模板方法 Template Method | B2 | 1 基类 | 步骤顺序本身不稳定 |
| 事件/观察者 Observer | U3, C2 | 1 事件契约 | 强一致/有序/需回滚的场景 |
| 密封接口+工厂 Sealed+Factory | B3 | 1 接口 | 类型集合开放增长(用注册表) |
| 数据版本迁移 Schema Versioning | D1, D2 | 1 版本机制 | 一次性数据、无历史兼容问题 |
| 管道/中间件 Pipeline | B2, C2, D3, S1/S2/S3 | 1 链契约 | 仅两步且不再增长 |

## 维度→候选模式映射

| 信号 | 候选(按成本升序) |
|------|-----------------|
| B1 | 配置外置 → 策略 |
| B2 | 模板方法 → 管道 |
| B3 | 密封接口+工厂 → 策略 → 注册表 |
| I1 | 防腐层 → 策略 |
| I2 | 策略 → 注册表 |
| I3 | 防腐层 → 适配器 |
| D1/D2 | 数据版本迁移 |
| D3 | 策略(数据访问) → 管道(分片/归档链) |
| C1 | 适配器 |
| C2 | 管道(批处理) → 观察者(异步解耦) |
| C3 | 注册表 |
| S1/S2/S3 | 管道 → 策略 |
| P1/P2 | 特性开关 / 配置外置 |
| P3 | 配置外置 |
| U1 | 配置外置(资源外置) → 适配器(格式转换) |
| U2 | 策略(权限校验点) |
| U3 | 观察者 → 注册表 |
| T1/T2/T3 | 防腐层(隔离边界)→ 适配器 |

## 选择协议

1. 按变化点命中的信号查上表得候选(通常 2-3 个),**抽象成本最低者优先**
2. 候选均不合身 → 允许 `[自定义机制]`:登记表标注 + 理由;后哨单独复核其必要性与抽象层数
3. 自定义机制被 ≥2 个项目复用 → 沉淀进项目模式清单;领域通用 → 提升回本目录(Layer 2,skill 维护者操作)
